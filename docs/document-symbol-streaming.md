# Document symbol streaming

Ordinary language servers continue to use standard hierarchical `textDocument/documentSymbol` results. Conversion resolves each distinct URI once per request and yields between short batches, so a large response remains cancellable while the editor handles input.

The IDE client advertises `capabilities.experimental.lumineDocumentSymbolChunks: 1`. A server supporting the same version advertises `capabilities.experimental.lumineDocumentSymbolChunks: 1`. When both sides support it, the client supplies a fresh `partialResultToken` on `textDocument/documentSymbol`; the server sends compact `$/progress` packets and ends with a `null` result. Requests without mutual negotiation or without a partial token retain the standard response. Adapters transforming document text or coordinates use the standard response and its existing projection mapping.

Each packet is `{ version: 1, offset: number, symbols: SymbolRow[] }`. `offset` is the number of symbols sent previously. Each row is `[name, kind, range, selectionRange, parentIndex]`, where `kind` is the standard LSP symbol kind, each range is `[startLine, startCharacter, endLine, endCharacter]`, and coordinates are zero based UTF-16 positions. Rows follow depth-first order, with every parent preceding its children; `parentIndex` addresses the complete stream, or is `-1` for a root. Both ranges are retained, so navigation continues to use the selection start while breadcrumbs and hierarchy use the structural range.

Packets contain at most 256 rows and target at most 48 KiB of serialized rows; a single unusually long symbol name may exceed that byte target. A large root is split across packets. The client validates the version, offsets, tuple shape, coordinates, kinds and parent indices before converting a packet. It exposes the same flat provider symbols as standard conversion, deriving `context` from the named parent. It never publishes an incomplete stream.

`LanguageServerSession.request` accepts an optional `onPartialResult(value)` callback for raw LSP partial results. Callbacks run in wire order, and the final promise waits for asynchronous callbacks. A callback failure aborts the outstanding request. Completion, cancellation, failure and session teardown retire its token and prevent late packets from entering the completed request. This callback receives server coordinates; callers using document projections must map them explicitly.
